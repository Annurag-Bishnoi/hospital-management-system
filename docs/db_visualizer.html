Architecture Overview (How to explain this in an interview)

1. Everything starts with the User: The system is secured using the users and roles tables. A physical person (Doctor, Patient, Nurse) logs in via the users table. From there, specific profiles (doctors or patients) extend the user entity (One-to-One) to hold domain-specific info like Specializations or Blood Groups. 2. The OPD Flow (Outpatient): A patient books an appointment. When they arrive, the doctor starts a visit. Inside a visit, the doctor records visit_vitals (temperature, BP), orders visit_lab_tests, and generates a prescription for medications. 3. The IPD Flow (Inpatient): If serious, a patient is moved to IPD via an admission. They are assigned a bed in a specific ward. Doctors perform daily_rounds to check progress, and nurses record nursing_charts throughout the day. 4. Supporting Pillars: The Pharmacy module manages physical stock via inventory_items and medicine_batches (FIFO logic for expiry dates). The Billing module consolidates all fees (OPD, IPD, Tests, Pharmacy) into bills and bill_items. The entire ecosystem uses medical_concepts (CIEL dictionary) to standardize terminology globally.
